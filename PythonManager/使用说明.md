Python 环境管家

主程序：D:\code\Python\PythonManager\PythonManager.exe

软件是独立 Windows EXE，使用 Windows 自带的 .NET Framework。管理界面不依赖 Python 启动；Python 安装损坏时仍可打开软件重新选择解释器。配有蓝黄 Python 主题图标，source 目录保留可重新编译的源码。

现有版本与默认

已检测并验证：Python 2.7.18、Python 3.9.13、Python 3.14.10，均为 64 位。保留 Python 3.14.10 作为日常默认，不删除或升级任何现有 Python，不改变 Java 环境。

Python 版本页

- 选择版本，点击“设为日常默认”：为新启动的普通终端设置 python 和 pip。修改前备份用户环境变量，只调整 Python 路径；保留 Java、C++、NodeJS 等其他工具路径。会备份并移除影响虚拟环境的用户 PYTHONHOME / PYTHONPATH 设置。
- 点击“独立 CMD”或“独立 PowerShell”：打开使用所选 Python 的终端，可同时打开多套版本，互不影响。使用 python 和 pip 命令。已有的 python2 / python39 / python314 等显式版本别名仍按原定义工作，py 启动器、IDE 和文件关联不由本软件强行改写。
- 点击“添加 Python”：选择新装 Python 的 python.exe，即可纳入列表。也会发现 D:\code\Python 下直接子目录及标准 PythonCore 注册表中的安装。不扫描软件自带运行环境和整块硬盘。

修改日常默认后，已打开的终端、IDE 或启动器不会自动刷新环境；关闭后重新打开即可。软件中的“独立终端”和题目环境会直接读取当前设置。

CTF 每题固定 Python 与依赖

1. 在“CTF 题目与依赖”页选择题目文件夹。
2. 选择题目要求的基础 Python，例如 2.7.18 或 3.9.13。
3. 点击“创建题目环境”，生成题目独享的 .ctf-venv，不继承基础 Python 和用户目录中安装的第三方包。
4. 在依赖列表中每行填写一个包，例如 requests==2.31.0，点击“安装填写的依赖”；也可点击“安装 requirements”选择题目提供的文件。安装只进入本题环境。
5. 点击“题目 CMD”“题目 PowerShell”，或者“用绑定版本运行脚本”。以后从最近题目列表载入即可，无需手动激活虚拟环境。

题目文件夹会生成：

- .ctf-venv：独立解释器与第三方包。
- .python-version：精确 Python 补丁版本。
- .python-environment.json：完整构建信息、架构、基础解释器与环境路径、核心文件指纹、依赖快照和解释器参数。
- python-environment.lock.txt：pip freeze --all 记录的依赖清单，包含 pip 等基础包。

启动前会验证基础解释器与环境指纹、Python 版本及依赖清单；缺失或变化时不会自动换用别的 Python。通过界面成功安装依赖后会自动更新清单。如果在题目终端手动安装了依赖，检查后点击“更新依赖记录”明确保存新状态。

版本绑定只对从本软件打开的题目终端和脚本生效。用其他终端直接进入题目目录不会自动切换。PyCharm / VS Code 的项目解释器应选择：题目目录\.ctf-venv\Scripts\python.exe。已打开的终端保持打开时环境。

已有绑定或 .ctf-venv 时不会覆盖。另一套版本可在另一题目文件夹中创建；若创建失败，会保留文件供检查，不自动删除项目内容。虚拟环境不适合直接复制或移动；需要移动题目时，保留源码与依赖清单，在新位置重新创建环境。虚拟环境仍依赖基础 Python，不要删除或覆盖其安装目录。

Python 2.7 兼容

Python 2.7 没有内置 venv，软件使用单独放在 tools 中的 virtualenv 20.15.1，由现有 Python 3.9 启动管理组件，实际题目解释器仍是 2.7.18。请保留 D:\code\Python\Python39。组件及依赖从 PyPI 下载并核对 SHA-256，来源记录与各组件许可文件一起保留；不会把管理组件安装进基础 Python 的 site-packages。

图形界面中的 Python 2 pip 操作为旧版 Windows 编码作了局部兼容处理，已测试含中文与空格的题目目录。CTF 脚本本身保持 Python 2 原生语义，不擅自修改脚本的默认编码。旧脚本、原生扩展和控制台 pip 仍可能有自身的中文路径限制，此时按题目要求使用英文路径。Python 2 只能安装支持它的旧依赖，界面会显示 pip 的实际错误与弃用提示。

运行脚本与日志

在第三页选择或拖入 .py / .pyw 文件。勾选题目绑定时，用本题环境和题目工作目录；否则用下拉框中的基础 Python，工作目录为脚本所在文件夹。解释器参数和脚本参数每行一个，不额外加外层引号。

解释器参数只在脚本运行功能中应用，不自动注入独立终端。输入交互型脚本请在题目终端中运行；界面运行功能关闭标准输入，并显示和记录输出。“停止当前任务”只停止当前脚本或 pip 进程，不保证关闭脚本自己启动的其他子进程。pip 任务超时为 10 分钟，创建环境超时为 3 分钟。

包管理会显示在同一日志页。默认使用 pip 自身的正常索引和 HTTPS 验证，不修改证书或全局 pip 配置，也不会自动安装题目文件中的依赖，需点击对应按钮。

依赖清单与复现范围

“导出依赖清单”导出精确包版本或 pip 记录的直接安装来源。清单是版本快照，不是包含全部 wheel 与 SHA-256 的可离线重建包；本地 wheel、editable 安装或 Git 依赖可能记录绝对路径/提交来源，需要一并保留这些文件。操作系统、外部服务、环境配置和题目依赖的原生库仍按题目说明准备。

虚拟环境用于依赖隔离，不是安全沙箱，脚本仍以当前用户权限执行。与是否能成功复现利用链无直接保证。

备份与源码

- data\settings.json：额外解释器、最近题目与默认选择。
- data\backups：用户环境变量、题目绑定及依赖清单更新前备份。
- data\logs：脚本和包安装日志。
- tools\legacy-host：Python 2 环境创建管理组件；请保留。
- tools\component-sources.json：组件来源、版本和下载 SHA-256。
- source\build.ps1：使用系统 C# 编译器重建 EXE，保留 assets 和 tools 即可。
